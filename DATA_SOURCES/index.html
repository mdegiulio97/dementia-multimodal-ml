    Parsing notes, both seen in the bytes read: the harmonised file has Windows line endings (the last field reads n_con\r), so strip \r; for flipped variants hm_beta has the opposite sign of beta (example rs1040232850: beta −0.2494, hm_beta 0.2494).

    Caveat for MR: sample overlap. The cohort list includes UK Biobank (proxy cases). The pQTL and mQTL sources below are also UK Biobank based, so exposure and outcome samples overlap in part. Overlap biases two-sample MR towards the confounded observational estimate, with a size that depends on instrument strength (Burgess, Davies & Thompson, Genet Epidemiol 2016, DOI 10.1002/gepi.21998 ✓). It must be stated, and a UK-Biobank-free outcome should be run as sensitivity:

    Sensitivity outcome: Kunkle et al. 2019 ⚠. Nat Genet, DOI 10.1038/s41588-019-0358-2, PMID 30820047 ✓; GWAS Catalog GCST007511 (21,982 cases, 41,944 controls, European, no UK Biobank), license "EBI terms of use" ✓. File https://ftp.ebi.ac.uk/pub/databases/gwas/summary_statistics/GCST007001-GCST008000/GCST007511/Kunkle_etal_Stage1_results.txt, 569,380,789 bytes, space-separated, header Chromosome Position MarkerName Effect_allele Non_Effect_allele Beta SE Pvalue ✓. It has no allele frequency, so palindromic SNPs cannot be resolved from the file and must be dropped. Build not stated in the folder (no meta file) ⚠: positions look like GRCh37 but this was not confirmed. Wightman et al. 2021 (PMID 34493870, GCST013196/GCST013197) also exists in the Catalog but includes UK Biobank as well, so it does not solve the overlap.

    5.1 What the DUA says (quotes from the current DUA unless noted)

    Individual-level data: redistribution is forbidden ✓.

    "I will not further disclose these data beyond the uses outlined in this agreement and my data use application. I understand that redistribution of individual participant-level data in any manner is prohibited. Reports and publication of summary (not participant-level) data are allowed." (term 3)

    "I will not disclose any participant-level raw or derived datasets beyond the uses outlined in this agreement. ... I understand derived datasets should only be shared through the ADNI-LONI and/or other NIA-designated data repository." (term 5)

    "I understand that I am not allowed to distribute ADNI data outside of my team, only the ADNI study website operated by LONI-IDA can distribute data." (term 6)

    Review by the Data and Publications Committee (DPC) ✓: required for manuscripts.

    "I will submit all manuscripts to the ADNI Data and Publications Committee (DPC) prior to submitting them to a journal. This review will not be a scientific review, but it is intended to ensure that the items above are correctly implemented. ... will complete its review within 2 weeks."

    The DSP Policy adds: "The ADNI DPC will not attempt to evaluate the scientific merit of proposed analyses, nor evaluate proposed abstracts. The DPC will be charged with the administrative review of manuscripts only." Submission route: IDA "My Account" → "Update" on the ADNI project → "Publication Update" tab, then e-mail the manuscript to the DPC (address in the DUA).

    Trained models ✓ (Appendix A).

    "investigators who intend on making the weights of a trained model publicly available should consider whether the model could be used to easily reconstruct parts of the ADNI data set. ADNI prohibits release of participant level data, even if it is sufficiently processed or altered and lack ADNI subject codes."

    AI tools ✓ (term 4, Appendix A). ADNI data may not be put into third-party AI tools that keep or reuse inputs, including "inclusion of ADNI data as part of an input or 'prompt' for a generative language model"; "opt-out" clauses are not "an acceptable safeguard". The exception is tools "developed and internally trained by individual research groups ... strictly used for the individual research group" with guaranteed containment.

    Data version ✓. "I will note the version (download date) of the data I download and provide this information in any Methods section".

    Small cells ✗. No minimum cell size is stated in the DUA, the DSP Policy or the citation guide. The agent's refusal below N = 10 is this project's own rule.

    5.2 Answer: can ADNI aggregates go on a public GitHub repository without DPC review? ⚠

    • Summary results are explicitly allowed (term 3: "Reports and publication of summary (not participant-level) data are allowed").
    • DPC pre-review is required for "manuscripts" before journal submission. No clause mentions websites, code repositories or software, so the DUA neither requires nor waives DPC review for a GitHub README with aggregate tables and figures. This is an inference from silence, not an explicit permission.
    • Individual-level data, raw or derived, must never be published, and this extends to anything that could reconstruct it: per-subject out-of-fold predictions and trained model files (a random survival forest stores training samples in its leaves).

    Conservative route if the owner sets publish_adni_aggregates: true: publish only aggregate metrics and figures (no per-subject points), with the acknowledgement text and the ADNIMERGE download date in the README; keep models/adni/ and conversion_predictions.parquet local; optionally notify the DPC through the IDA "Publication Update" route; any later manuscript goes through the DPC as required.

    Owner decision (2026-11-12): the conservative route. ADNI conversion results will be published as aggregate tables and figures only, with the acknowledgement below and the ADNIMERGE download date; models and per-participant predictions stay local. publish_adni_aggregates is set to true in the same commit that adds the first ADNI aggregates.

    5.4 Consequences for this repository

    • ADNI rows are never read by any cloud model, including the coding assistant used to build this repo; only the local agent (Ollama) touches ADNI tables, which is the "internally contained" case of Appendix A. The MCP server refuses ADNI mode unless explicitly allowed for a local client.
    • models/adni/ and per-subject predictions stay in gitignored folders even if aggregates are published.
    • Provenance blocks record the download date of each ADNI table.
    • DX_bl also takes the value MCI for ADNI3 recruits (see the download list), so the MCI set is {"EMCI", "LMCI", "MCI"}.

    All three are PubMed records read on 2026-11-12; numbers are quoted from the abstracts.
